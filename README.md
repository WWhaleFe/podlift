# Podlift

아이팟 클래식 음악 관리 macOS 앱. iTunes·Finder 동기화 없이 다음을 한다.

- **가져오기**: 아이팟 안의 뒤섞인 이름(`iPod_Control/Music/F00/ABCD.m4a`) 파일을 태그로 되살려
  `가수/앨범/[디스크-]트랙 제목.확장자` 구조로 내 폴더에 복사한다. 곡을 골라 아이팟에서 지울 수도 있다
  (곡 DB 에서 빼고 파일은 아이팟 안에 치워 둠, '마지막 작업 되돌리기'로 되돌림. 직접 고른 폴더면 휴지통).
- **아이팟에 넣기**: 곡을 아이팟에 복사하고 곡 DB(`iTunesDB`)에 직접 등록한다. 앨범 아트도 그림 DB(`ArtworkDB`)에 넣는다.
- **중복 정리**: 맥 폴더 또는 아이팟 안에서 같은 곡을 묶어 음질(그다음 앨범 아트)이 나은 것만 남긴다.
  폴더는 나머지를 휴지통으로 옮기고, 아이팟은 곡 DB 에서 빼고 파일을 아이팟 안에 치워 둔다. '다시 검사'로 남은 중복을 다시 훑는다.
  묶음마다 기본은 라디오(한 곡 남기기)이고, '여러 곡 남기기'를 켜면 체크박스로 여러 곡을 남긴다. '모두 지우기'로 묶음 전체를
  지울 수도 있다(아이팟은 재생 목록에서도 빠진다). 줄이나 앨범 아트를 눌러도 고르고, 키보드는 ↑↓ 곡 이동(곡만 오간다),
  스페이스 고르기, 같은 묶음에서 스페이스 두 번이면 라디오 ↔ 여러 곡이 바뀐다.
- **AI로 중복 찾기**: 가수·그룹·앨범 이름이 한국어/영어로 달라 자동으로 못 찾은 중복은, 곡 목록을 CSV 로 내보내
  AI 에게 요청문과 함께 주고(같은 곡끼리 `group` 칸에 같은 값), 그 CSV 를 불러오면 그대로 묶어 중복 정리 화면에서 처리한다.
  칸: `id, group, keep, title, artist, album_artist, album, track, duration, quality, size_bytes, path`.
  `path`(정리할 곳 기준 상대 경로)로 곡을 찾고, `keep` 이 1 인 곡을 남길 곡으로 고른다(csvlist.rs).
- **폴더 정리**: 맥 음악 폴더를 '가수/앨범/트랙 제목' 구조로 옮기고(되돌리기 가능), 앨범 아트가 없는 곡 파일에 그림을 심는다.
- **앨범 아트**: 같은 앨범 곡의 그림 → 폴더의 cover.jpg → 온라인 검색(MusicBrainz·iTunes, 무료) 순으로 찾는다.
  '다른 앨범에서…'를 누르면 그림이 있는 다른 앨범을 이름이 비슷한 순서로 보여 주고(검색 가능), 고른 앨범의 그림을 쓴다.
  이 창들은 운영체제 별도 창이라 앱 창 밖으로 옮길 수 있다(popup.rs).
  아이팟에 이미 있는 곡에도 채울 수 있다('아이팟에 넣기' 탭). 아트 없는 곡이 있으면 안내 띠가 뜨고 '앨범 아트 한 번에 채우기'를
  누르면 곡 파일 속 그림 → 같은 앨범의 아이팟 그림 → 온라인 검색 순으로 찾아 한 번에 채운다(Finder 동기화 뒤에 그림 연결이
  모두 빠졌을 때 쓰기 좋다). 앨범마다 골라서 채우려면 '앨범 아트 채우기…'.

- GUI: Rust + eframe(egui) 0.37, 테마·폰트는 Podfill 과 같은 코드. 아이콘은 Podfill 아이콘 생성기(`tools/make-icon.py`)의
  sunset 테마로, Podfill(보라)과 구분되게 주황·분홍이다
- 태그·음질 읽기: lofty / 변환: macOS 내장 `afconvert` (추가 설치 없음)

## 설치 (Homebrew)

```
brew install --cask wwhalefe/tap/podlift
```

새 버전: `brew update && brew upgrade --cask podlift`. Apple Silicon(arm64) Mac, macOS 12 이상.
공증(notarize)하지 않은 앱이라 cask 가 설치할 때 격리 표시(quarantine)를 지운다.

새 버전 내기: `Cargo.toml` 의 `version` 을 올리고 커밋한 뒤 `./release.sh "바뀐 점"`. 앱을 만들어 GitHub 릴리스
(`podlift-macos-arm64-<버전>.zip`)로 올리면, 탭의 Bump 워크플로가 30분 안에 cask 를 새 버전으로 바꾼다.

## 빌드·설치 (소스에서)

```
./build-app.sh            # Podlift.app
./build-app.sh --install  # 만든 뒤 /Applications 에 설치(교체)
```

## 삭제와 키보드 (listkeys.rs, popup.rs)

- 가져오기 곡 목록, 중복 정리 묶음, 폴더 정리의 앨범 아트 목록에서 골라 지울 수 있다. 전체 선택·전체 해제 단추가 있다.
- 삭제 단추나 Delete 키를 누르면 경고창이 한 번 더 뜬다. 뒤 화면은 누를 수 없고, Esc·취소로 닫힌다(엔터로는 지우지 않는다).
- 키보드: ↑↓ 이동, 스페이스 선택, ⌘A 전체 선택, Esc 전체 해제, Delete 고른 것 삭제. 중복 정리에서는 스페이스가
  '남길 곡 고르기'라서 묶음 선택은 X 키다. 글자 입력 칸에 있을 때는 키를 가져가지 않는다.
- Mac 파일은 휴지통으로, 아이팟 곡은 곡 DB 에서 빼고 파일을 `.podlift-old` 로 옮긴다.
- 창은 처음 열 때 모니터 높이에 맞춰 세로로 길게 연다(최대 1200pt). 중복 정리 결과를 볼 때는 위쪽 설명을 한 줄로 줄이고
  곡 줄을 낮게 그려 묶음 하나가 한 화면에 들어오게 하며, ↑↓로 다른 묶음에 가면 그 묶음 전체가 보이게 굴린다.

## 같은 곡의 기준 (audio.rs same_song_groups)

대소문자·공백은 무시하고, 아래 중 하나면 같은 곡으로 묶는다(이어지면 한 묶음).

- 앨범 + 제목이 같고, 가수가 같거나 가수 표기만 다르고 길이가 3초 안으로 같다
  (드림캐쳐/Dreamcatcher 는 묶고, 같은 이름 싱글에 든 다른 가수의 같은 제목 곡은 묶지 않는다)
- 앨범이 달라도 제목 + 가수가 같다 (싱글과 정규 앨범, 일반판과 디럭스판). 길이가 10초 넘게 다르면 '확인 필요'

아이팟에 넣기의 '이미 있음·더 좋은 음질·목록 중복' 판정도 같은 기준을 쓴다. 넣기 화면의 '겹치는 곡' 칸에 어느 아이팟 곡
(또는 목록의 몇 번째 곡)과 겹치는지 나오고, 중복으로 판정된 곡을 직접 체크해 넣으려 하면 한 번 더 묻는다.

## 음질 비교 규칙 (audio.rs)

같은 곡 중 무엇을 남길지:

1. 무손실(ALAC·FLAC·WAV·AIFF) > 손실 압축(AAC·MP3)
2. 둘 다 무손실이면 샘플레이트 × 비트 깊이
3. 둘 다 손실이면 비트레이트가 8% 넘게 높은 쪽, 비슷하면 샘플레이트
4. 여기까지 같으면 앨범 아트: 있는 쪽, 해상도가 큰 쪽
5. 그래도 같고 형식(코덱)·샘플레이트·비트 깊이·아트 크기까지 같으면 '같은 사본' - 비트레이트(그다음 파일 크기)가 큰 쪽을 남긴다
6. 그 밖(예: 비트레이트가 비슷한 MP3 와 AAC)은 '확인 필요' - 사용자가 고른다. 아이팟 정리에서는 처음에 '그대로 두기'로 둔다

중복 정리는 길이가 10초 넘게 다른 묶음을 다른 버전(라이브·리믹스)일 수 있다고 보고 '확인 필요'로 둔다.

## 아이팟에 넣기 (itunesdb.rs, sync.rs)

형식은 libgpod(`itdb_itunesdb.c`, `itdb_hash58.c`)를 따랐다.

- **DB 를 새로 만들지 않는다.** 읽은 청크 나무를 그대로 두고 필요한 곳만 고친다.
  열 때 "읽은 그대로 다시 쓰면 원본과 한 바이트도 다르지 않은지" 확인하고, 다르면 쓰기를 막는다.
- 새 곡은 곡 목록(mhlt)과 기본 재생 목록(mhsd 2·3) 끝에 덧붙인다. 기존 곡 번호·위치가 바뀌지 않아
  재생 횟수 파일·On-The-Go 목록이 그대로 맞는다. 앨범(mhsd 4)·가수(mhsd 8) 목록도 있으면 함께 늘린다.
- 기본 재생 목록의 정렬 색인(mhod 52)과 글자 건너뛰기 표(mhod 53)는 아이팟이 노래·가수·앨범·장르·작곡가
  메뉴를 그리는 데 쓴다. iTunes·Finder 가 만든 색인(정렬 종류 10가지)은 순서를 그대로 두고, 뺀 곡만 지우고
  새 곡만 알맞은 자리에 끼운다. 곡 구성이 그대로면 손대지 않아 DB 가 원본과 바이트까지 같다.
  색인이 없을 때만 libgpod 처럼 5가지를 새로 만든다.
- 정렬 규칙은 한국어 맥이 만든 실제 색인과 맞춰 정했다: 앞쪽 문장 부호 무시, 대소문자·악센트 무시,
  첫 글자 종류 순서 한글·한자 → 라틴 → 가나 → 숫자. Apple 은 한자를 한글 읽기로 놓아 그 부분만 다르다.
- **음질이 더 좋은 같은 곡**은 새 레코드를 만들지 않고 기존 레코드의 파일만 바꾼다
  (재생 횟수·별점·재생 목록 유지). 옛 파일은 `iPod_Control/Music/.podlift-old/` 로 옮겨 둔다.
- 쓰기 전에 `iTunes/iTunesDB.podlift-<시각>` 으로 백업하고, 작업 기록을 `iTunes/podlift-last-job.json` 에 남긴다.
  '마지막 작업 되돌리기'는 DB 를 백업으로 되돌리고, 넣은 파일을 지우고, 옛 파일을 제자리에 돌려놓는다.
- hash58 서명: 아이팟 클래식은 DB 에 기기 고유 번호(FirewireGuid)로 만든 서명이 있어야 곡 목록을 읽는다.
  고유 번호는 `Device/SysInfo` → `Device/SysInfoExtended` → USB 일련번호 순으로 찾는다.
  서명 계산은 libgpod 원본 C 코드를 그대로 컴파일한 결과와 일치함을 확인했다.
- 아이팟 클래식이 못 읽는 형식(FLAC·OGG·Opus)과 48kHz·16bit 를 넘는 고해상도는
  `afconvert` 로 ALAC 16bit(무손실) 또는 AAC 256kbps 로 바꾸고 원본 태그를 옮겨 붙인다.
- 서명 방식이 hash72·hashAB 인 기기(나노 5세대 이후, 터치)와 압축 DB(iTunesCDB)는 쓰지 않는다.
- 고유 번호를 USB 정보에서 찾을 때 macOS 26 부터는 `SPUSBHostDataType`(키 `USBDeviceKeySerialNumber`)을 본다.

### 아이팟 중복 정리 (ipod_dedupe.rs)

- 중복 찾기는 맥 폴더와 같은 규칙으로 `iPod_Control/Music` 을 훑고, 파일 경로로 곡 DB 의 곡을 찾는다.
- 뺄 곡이 든 재생 목록에는 남길 곡을 대신 넣는다(이미 있으면 지운다). 재생·건너뛴 횟수는 더하고,
  별점·마지막 재생 시각은 큰 쪽을 남긴다. 곡이 남지 않은 앨범(mhsd 4)·가수(mhsd 8) 항목은 지운다.
- `iTunes/Play Counts`(곡 목록 순서대로의 재생 기록)가 있으면 뺀 곡의 항목도 같이 뺀다.
- 파일은 `iPod_Control/Music/.podlift-old/Fxx/` 로 옮겨 둔다. '마지막 작업 되돌리기'로 DB·재생 횟수 파일·파일을
  모두 되돌리고, 다음 넣기 작업을 시작할 때 이 폴더를 비운다(그때 용량이 실제로 비워진다).

### 앨범 아트 (artworkdb.rs)

형식은 libgpod(`db-artwork-writer.c`, `ithumb-writer.c`)를 따랐다.

- 그림 원본: 곡에 든 앞표지(없으면 첫 그림), 그것도 없으면 같은 폴더의 `cover`·`folder`·`front`·`albumart` `.jpg/.png`.
- 아이팟 클래식 형식 4가지(1061: 55², 1055·1068: 128², 1060: 320²)로 비율을 지켜 줄이고 남는 곳을 검은색으로 채운
  RGB565(리틀 엔디언) 픽셀을 `iPod_Control/Artwork/F<형식>_<번호>.ithmb` 끝에 덧붙인다(파일당 256MB 까지).
  형식은 기존 ArtworkDB 의 mhif → SysInfoExtended 의 AlbumArt → 모델 번호(클래식·3세대 나노) 순으로 정한다.
  실제 클래식은 1061 을 55x55 로 그리고 한 줄을 56픽셀(4바이트 단위)로 맞춰 6160 바이트에 담는다
  (libgpod 의 RowBytesAlignment). libgpod 기본 표의 56x56(6272 바이트) DB 도 받는다.
  모르는 기종이나 모르는 형식이면 그림만 건너뛰고 곡은 넣는다.
- ArtworkDB 는 곡 DB 처럼 읽은 그대로 두고 그림 항목(mhii)만 덧붙인다(되쓰기 확인 동일).
  곡(mhit 0x160)이 그림 번호를 가리킨다.
- 같은 앨범의 같은 그림은 한 장만 저장해 같이 쓰고, 아이팟에 그 앨범 그림이 이미 있으면 그 번호를 쓴다.
- 되돌리기용으로 ArtworkDB 백업(`Artwork/ArtworkDB.podlift-<시각>`)과 ithmb 의 원래 길이를 작업 기록에 남긴다.
  곡 DB 쓰기가 실패하거나 되돌리기를 누르면 ArtworkDB 를 되돌리고 ithmb 를 원래 길이로 자른다.
- 확인: 쓴 결과를 libgpod 구조체 정의만 보고 짠 별도 해독기로 다시 읽어 그림이 원본과 같게 나오는 것을 봤다.

### 앨범 아트 온라인 검색 (artsearch.rs)

- MusicBrainz 음반 검색(한글·일본어 가수 이름도 별칭으로 찾음) → Cover Art Archive 앞표지, 없으면 iTunes 검색(미국·일본).
- 앨범 이름이 사실상 같고(" - Single", "(Deluxe…)" 꼬리 무시) 가수가 맞을 때만 받아들인다. 보내는 것은 앨범·가수 이름뿐.
- MusicBrainz 는 초당 1번 제한이 있어 1.1초 간격으로 묻고, 바쁘면 3초 기다렸다 다시 묻는다.
- 받은 그림은 `~/Library/Caches/Podlift/art/` 에 두고, 넣기 전에 미리 보기로 확인한다.

### 되돌리기와 Finder 동기화

- '마지막 작업 되돌리기'(아이팟)는 작업 기록에 남긴 곡 DB 지문(SHA-1)과 지금 DB 가 같을 때만 된다.
  Finder·Music 동기화가 그 사이 DB 를 다시 썼으면 옛 DB 로 덮어쓰지 않도록 막는다.
- Finder 가 자동 동기화하는 아이팟은 다음 동기화 때 Mac 보관함 기준으로 다시 맞춰진다. 아이팟 쪽 정리를 오래 두려면
  Finder 에서 '음악을 수동으로 관리'로 두거나 Music 앱 보관함 쪽 중복도 정리해야 한다.

### 아직 안 되는 것

- 이미 아이팟에 있는 곡에 앨범 아트 새로 붙이기 (넣는 곡에만 붙인다)
- 아이팟에서 곡 지우기, 재생 목록 만들기
- 아이팟 화면에서의 확인: 실제 아이팟(512GB 개조, FAT32)의 DB 읽기·서명·되쓰기와 중복 정리 쓰기는 확인했지만,
  넣기와 앨범 아트 쓰기는 아직 가짜 아이팟으로만 시험했다

## 개발·점검용 환경 변수

| 변수 | 하는 일 |
|---|---|
| `PODLIFT_TAB=sync\|dedupe\|organize` | 시작 탭 |
| `PODLIFT_OPEN=<폴더>` | 가져오기 탭에서 그 폴더를 아이팟처럼 연다 |
| `PODLIFT_SYNC_ADD=<폴더>` | 넣을 목록에 그 폴더의 곡을 미리 담는다 |
| `PODLIFT_DEDUPE_DIR=<폴더>` | 중복 정리 탭에서 그 폴더를 바로 훑는다 |
| `PODLIFT_ORGANIZE_DIR=<폴더>` | 폴더 정리 탭에서 그 폴더를 바로 훑는다 (`PODLIFT_ORGANIZE_MODE=art` 면 앨범 아트 넣기) |

테스트 중 일부는 환경 변수가 있을 때만 실제 파일로 돈다:
`PODLIFT_FAKE_IPOD`, `PODLIFT_DEDUPE_DIR`, `PODLIFT_SYNC_TEST` + `PODLIFT_SYNC_SRC`, `PODLIFT_HASH_OUT`.

실제 아이팟 점검(`real_ipod_check.rs`): `PODLIFT_REAL_IPOD=/Volumes/<이름>` 이면 읽기만 한다
(연결·서명·되쓰기·색인 확인, 곡 하나 빼기 모의). `PODLIFT_REAL_DEDUPE=1` 을 더하면 중복 찾기와 정리 모의 실행,
`PODLIFT_REAL_OUT=<폴더>` 면 목록과 모의 DB 를 남긴다. `PODLIFT_REAL_APPLY=yes-write` 는 실제로 정리하고,
`PODLIFT_REAL_ART_APPLY=yes-write` 는 실제로 앨범 아트를 채운다. `PODLIFT_REAL_ART=1` 은 채울 수 있는 앨범 수만 센다.
